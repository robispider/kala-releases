# Maintaining the bilingual website

The Astro + Starlight website publishes at [robispider.github.io/kala-releases](https://robispider.github.io/kala-releases/). English and Bangla pages live at `/en/` and `/bn/`, with a language selector that keeps the same page.

## Edit the content

English content stays in `USER_GUIDE.md` and `docs/`. Complete Bangla translations mirror those paths in `translations/bn/`. Keep filenames, key recipes, output text, numerical results, and link targets aligned between languages. Translate explanatory prose and headings; retain exact app control names alongside Bangla explanations so users can find them.

`site/scripts/content-map.mjs` maps the Markdown sources to website routes. `npm run sync` generates Starlight pages and rewrites repository `.md` links into the correct language routes. Generated pages are ignored by Git: edit the canonical Markdown, not `site/src/content/docs/`.

The two homepages are generated by the same script and share `site/src/components/KalaHome.astro`. The homepage uses the existing research JSON snapshot for search-run counts; named layout comparisons stay on the research page. Bangla navigation/search labels are in `site/src/content/i18n/bn.json`; styling is in `site/src/styles/kala.css`.

## Preview locally

Use Node.js 24 (Node >=22.12 is supported by the locked toolchain):

```powershell
cd site
npm ci
npm run dev
```

Open the printed local address with `/kala-releases/en/` or `/kala-releases/bn/`. After changing canonical Markdown, run `npm run sync` in another terminal or restart the dev server. To test the production search index, build and preview:

```powershell
npm run build
npm run preview
```

## Check and publish

`npm run build` checks completeness of all language pairs, link targets, inline code/paths, step/headings/table counts, research table numbers, and fixed-layout key maps. It builds both languages, then checks generated local links/assets/headings, same-page language destinations, and the search index.

In GitHub **Settings → Pages → Build and deployment → Source**, choose **GitHub Actions**. The workflow `.github/workflows/pages.yml` builds from the locked dependencies and publishes changes pushed to `main`. Pull requests build/check the site without deploying. **Actions → Publish bilingual Kala guide → Run workflow** can manually rebuild it.

Installers remain attached to GitHub Releases. The website links to those downloads; it does not include the large setup executable in its Pages artifact. Publishing the website does not publish Kala's application source.

## Latest release references

Download buttons, the homepage release line, the README and the installation guides point at the newest published release automatically. `.github/workflows/latest-release.yml` runs when a release is published, unpublished or deleted, when `site/public/updates/withdrawn.json` changes, or manually from **Actions → Point website and guides at the latest Kala release**. It picks the highest non-draft, non-withdrawn version that has a `KalaSetup-<tag>.exe` asset, writes `site/src/data/latest-release.json`, commits the changed text to `main`, and starts the Pages workflow.

The workflow changes only text inside these markers, so review statements such as “reviewed against v0.1.0-alpha.1” stay accurate:

- `<!-- kala:latest -->…<!-- /kala:latest -->` — every version, `KalaSetup-v….exe` name, and release tag/download URL inside is replaced with the latest release's values. Other files on a download URL, such as `SHA256SUMS.txt`, keep their names.
- `<!-- kala:latest-channel -->…<!-- /kala:latest-channel -->` — replaced with the release type: “an **alpha pre-release**”, “a **stable release**”, and so on; in Bangla “**আলফা প্রি-রিলিজ**”, “**স্টেবল রিলিজ**” (write “যা একটি” before it).

Write the surrounding sentence so it reads correctly for any version, for example “The latest release is …”. A marker must open and close on one line, and English and Bangla pages must carry the same markers in the same order. `npm run check` fails on a broken marker or on marked text that differs from `latest-release.json`. To update by hand, run `node site/scripts/update-latest-release.mjs` from the repository root. The site removes the markers from generated pages.

## Translation and asset notes

Bangla guides are maintained translations, not an automatic browser-translation widget. The build fails if a language pair is missing or preserved facts drift. Review the meaning when changing either language; structural checks cannot prove translation quality.

Write Bangla in a natural, formal Bangladeshi style, with short instructions and familiar Windows terminology. Use **কিবোর্ড লেআউট**, **উইন্ডো**, **পেজ**, **ওয়েবসাইট**, **ইমপোর্ট**, **এক্সপোর্ট**, **কপি**, **পেস্ট**, **টুলস**, **সাজেশন**, and **টেক্সট ডেটাসেট**. Refer to letter keys as **অক্ষর** and modifier/action controls as **বোতাম**, retaining their printed names (Shift, Ctrl, Alt, Space). Use **কালা**, **কালা ঝড়**, and **কালা গতি** in Bangla prose; keep exact English app labels where they help users find a control. Preserve literal typing examples such as **কি** and **কী**, key sequences, paths, placeholders, and research figures. Avoid literal English sentence structures and terminology specific to mobile apps.

The site reuses Kala's existing mark and Black Bengal goat mascot. Fonts are self-hosted through the locked Inter and Noto Sans Bengali packages; their license notices are published with the site. The layout model results remain qualified as modeled effort, with human trials pending. Learn ships with the standard release under the user decision of 12 October 2026. UniJoy/UniBijoy is not bundled; historical mappings and benchmarks remain research references. Keep older installer availability distinct from the next release.

The homepage hero is `site/src/components/AppHero.astro`. It preserves the mascot's full portrait dimensions instead of Starlight's default square image crop. The app keeps its green product design; kala-layout uses a separate blue research design. Layout-origin links on the homepage and research guide lead to the matching language on kala-layout. Canonical paired Markdown keeps English research URLs; `rewriteLinks` localizes them when building the site.
